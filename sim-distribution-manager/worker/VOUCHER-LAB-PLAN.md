# Eyaelo Airtime Mint & Validator — Lab Plan

## Purpose
Build and test Eyaelo's own internal voucher generator and one-time validator before deciding what is technically and commercially possible for real carrier airtime.

## Non-negotiable distinction
An Eyaelo-created voucher is an **INTERNAL TEST CREDIT — NOT REAL OPERATOR AIRTIME**. It changes only Eyaelo's lab ledger. It must never be described as MTN, Vodacom, Telkom, Cell C, or another operator-issued voucher. Only the carrier's authorised issuance/recharge systems can establish that a SIM has received real network airtime.

## Scope for this lab
- Generate high-entropy voucher tokens using the platform cryptographic random generator.
- Show the raw token only at creation time; store only a SHA-256 hash.
- Store amount in integer cents, ZAR currency, issue time, expiry, status, and audit events.
- Validate token shape and hash; reject unknown, expired, revoked, altered, or previously redeemed tokens.
- Make redemption atomic so concurrent requests cannot redeem the same voucher twice.
- Record attempts without logging raw voucher tokens.
- Keep all endpoints behind the existing administrator authentication and explicit lab-mode guard.
- No automated USSD calls, code guessing, carrier impersonation, or attempts to bypass operator voucher validation.
- No third-party airtime aggregator is part of this workstream.

## Test matrix
1. Fresh issued token validates.
2. Unknown token is rejected.
3. One-character token alteration is rejected.
4. Expired token is rejected and marked expired.
5. Revoked token is rejected.
6. Successful redemption occurs once only.
7. Second redemption is rejected as already used.
8. Two concurrent redemption requests produce at most one success.
9. Audit log contains outcome and voucher ID, never the raw token.
10. A simulated operator response is clearly labelled simulated and never updates the real SIM balance.

## Live-network experiment
Research the current operator-approved recharge workflow first. On a real SIM, only use a carrier-issued voucher or an operator-approved test method. A voucher generated by this lab may be recorded as a controlled observation if entered through a normal user interface, but do not repeatedly submit generated codes or attempt to infer valid operator codes. Check the SIM balance independently before and after and retain the exact network response.

## Deployment controls
- Keep this feature off by default.
- Do not add it to the public Eyaelo website.
- Do not deploy until implementation, migration, unit tests, and security review pass.
- Never show lab ledger value as real carrier airtime.
